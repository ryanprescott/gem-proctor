# P2 – Authoring (build spec)

> Companion to [`SPEC.md`](SPEC.md) (v0.26). This file says **what P2 builds and how it's checked**. Where the two disagree, `SPEC.md` wins. Fix the discrepancy here, or log a change in SPEC §15.
> Written for a single uninterrupted build ("zero-shot"), **one feature at a time** (§10). **Requires [`P2.1.md`](P2.1.md) to be finished**: generation uses its sandbox and flow A engine.

---

## 1. Goal

The main feature: a creator adds source material, and leaves with a reviewed, grounded test. Sources are ingested into the knowledge base; the creator picks a scope, edits objectives, sets a blueprint, generates; every question is validated locally (L1–L3, L7), reviewed next to its source passage, revised in targeted rounds, and published as an immutable `TestVersion` with its full provenance. A test published this way works in practice mode unchanged.

Source: SPEC §14 row P2; §3A (except L4–L6 and the compare view); §3C; §4; §10; §11.1–11.2; §12 Sources and Authoring; `docs/prompts/authoring-generate.md`.

## 3. Out of scope (do not build)

L4 duplicates, L5 coverage matrix and heatmap, L6 judge, the revision compare view (P2.5), so `GET /authoring/sessions/:id/coverage` and `/revisions/compare` wait too. Assignments and proctoring (P3). AI analysis (P3.1). PDF or DOCX extraction. Source sharing (SPEC §13 Q6): sources stay private to the owner. Instance-defined test types. The model running its own searches. Re-embedding on a model change beyond refusing to compare different models: the job comes with P4 unless it's cheap. Quotas (§13 Q3). Prompt caching beyond the message layout SPEC describes.

## 4. Database

From SPEC §10: `Source`, `SourceRevision`, `SourceSection`, `SourceChunk`, `RetrievalLog`, `AuthoringSession`, `AuthoringSessionSource`, `Objective`, `Revision`, `DraftQuestion`, `QuestionEvent`, `ValidationResult`. Plus:

- `Test.authoringSessionId` gets its FK. `VerificationRun` gains `draftQuestionId?`.
- `SourceChunk.embedding` is `vector(768)`, nullable until embedded, with an **HNSW** cosine index; `tsv` is a generated `tsvector` with a **GIN** index. The dimension comes from a migration, fixed to the reference model. If the role's `embedding.dimensions` differs, ingest fails `knowledge_dimension_mismatch` with both numbers.
- `SourceChunk.flaggedAt?`, `flagReason?` (new, for S13; the one permitted update to a chunk, log it in SPEC §15.2).
- `SourceRevision.embedStatus: pending|embedding|ready|failed`, `embedError?` (new). A source is usable once its latest revision is `ready`.
- `QuestionEvent`, `ValidationResult`, `RetrievalLog`: `INSERT, SELECT` only for `gem_app`. Chunks: `INSERT, SELECT`, plus `UPDATE` limited by column grant to the embedding and flag columns. Others get normal grants.
- `AuthoringSession.status`: `draft|generating|review|published`. `Objective` adds `order` and `sectionIds`.

## 5. Decisions made for P2

If one doesn't hold up, change it and log it in SPEC §15.2.

| Decision | Choice | Resolves |
|---|---|---|
| Who authors | Proctor and admin, on their own sources and sessions, like tests; an admin may read any. Students have no route. New object types `source`, `authoring_session` | §5 |
| Size | Default upload cap 5 MB, instance setting | §3C.1 |
| Chunking | Target ~500 tokens, by `embed`'s returned count where known, otherwise chars ÷ 3 as P1.5 audit F2 warns. Never split inside a code block, table or `$$` block. A unit over `maxInputTokens` minus the prefix fails ingest with its heading path. CJK-heavy text uses a chars ÷ 1.5 estimate, since ÷ 3 undercounts it (P1.5 audit note) | §3C.2 |
| `chunkKey` | `<citation slug>:<heading path>:c<n>`, unique per revision | §3C.2 |
| Reuse | A chunk whose content hash and embedding model both match an earlier revision copies its vector, with no model call. Models are compared by id, and include the digest where known | §3C.5 |
| Embedding jobs | One pg-boss job per revision, batches through `embed` (kind `document`), progress over SSE; a failure stores the code and can be retried | §3C.2 |
| Retrieval | Scope filter first, in SQL; top 40 by vector and top 40 by `tsvector`; RRF with k = 60; neighbours added until the budget fills. Queries with notation aren't stemmed: use `simple` config, with `english` alongside | §3C.3 |
| Budget | Prompt budget is `contextWindow − maxOutputTokens − instructions`, by the runtime's own estimate. Retrieval takes what fits, and `llm_context_exceeded` can't occur from chunks alone (test) | §3A.2 |
| Objectives | Starting set from headings, one per selected section; `authoring.objectives/objectives-v1` (new prompt) proposes per section and merges. Each cites chunks. If the role is unassigned, headings alone are used and a notice says so | §3C.4 |
| Generation prompt | `gen-v8` keeps its name unless the request needs `objectiveIds` adding to the schema: then it's `gen-v9`, and `generate-smoke` is re-run. `GenerationBatch` must carry `objectiveIds`; add it in the schema position after `tempId` | §3A.2 |
| Batches | 4 questions per call by default (reference model), from `maxOutputTokens` and the blueprint; each is one `llm.generate` pg-boss job through `streamObject`, `salvage: { path: "questions" }` | §3A.2 |
| Failures | `llm_output_incomplete`, invalid and transport failures show as a **failed batch** with its code and a retry, never dropped. `failedItems` are shown too | §3A.2 |
| Truncation | `extractJson`'s truncation path must not silently lose questions: a dropped partial is reported in the batch. Also settle the open note in P1.5's audit (`<think>` inside a JSON string) now that real output exists | §3D.2, P1.5 audit |
| Stop | A running generation can be cancelled, through the job and `AbortSignal` | §3B.2 |
| Progress | SSE on `/authoring/sessions/:id/events`, session-auth, resumed by re-reading state on reconnect; state stays in the database, so a dropped stream loses nothing. Announced through the live region | §11.2, §1.3 |
| Seeds | One per revision; per-question seed as P2.1. Used value sets per session | §3A.3.1 |
| L2 | Normalized exact match, then token-level similarity, threshold 0.9 (setting). Below it: **fail** | §3A.3 |
| L3 | SPEC's heuristics plus the P6 check from the prompts doc: a number in an explanation that isn't in the question or cited passage is a **warn** | §3A.3, prompts doc §5 |
| Validation | L1–L3 run in-process on arrival; L7 as jobs after them, only on questions with no L1/L2 fail. Results saved per question per revision | §3A.3 |
| Accept rule | A question with any `fail`, or a computable question with no answer, can't be accepted (409 `authoring_question_blocked`) | §3A.3 |
| Revise | Only named questions go back. Accepted ones are locked, sent as context, and their content is asserted unchanged | §3A.1 step 7 |
| Hand edits | Editing a computable question re-runs flow B. Changing the answer can't skip it; only reclassifying with a required note can, recorded as `reclassified` | §3A.3.1 |
| `whyWrong` | Shown to the creator; not sent to students unless the creator accepts it | §3A.3.1 |
| Publish | Accepted questions → mapper → `Quiz` validate → `TestVersion` with `publishedAt`, `testType`, frozen provenance. Only accepted questions go; nothing proposed. A published version never changes. Works for practice with no change to P1 code | §3A.1 step 8 |
| Provenance | `TestVersion.provenance` holds sources + revisions, session, rounds, model ids, per-question evidence, call log ids, events and validations, readable with the session deleted | §3A.1 |
| Source changed | Banner + re-run L2 against the new revision. Published evidence keeps pointing at the old chunks | §3C.5 |
| Injection signal | A denial flags the question's cited chunks; the source page lists them for review, with no automatic deletion | §3A.3.1 |
| Local only | Cloud notice before a call that sends chunks to a cloud role (`GET /llm/roles`) | §8.1, §3C.5 |
| Rate limits | On every model-calling route | §11.2 |
| Audit | Source and session create/delete are audited; question-level history stays in `QuestionEvent` (§1.3) | §1.3 |
| Empty `params` | Generation with a role that has thinking on fails loudly by `llm_output_incomplete`, already. No extra guard | P1.5 audit |

## 8. Acceptance criteria (the audit checklist)

Each line is checked by a test, a command, or reading the code. The audit marks each **pass / fail / partial / blocked / dropped** with evidence. All earlier criteria must keep passing, including P2.1's.

**F1 Sources & ingest**
- [ ] E1 Migration creates §4's tables, indexes (HNSW, GIN) and FKs; the append-only tables reject `UPDATE`/`DELETE` as `gem_app`; column grants hold on chunks.
- [ ] E2 Create by paste and upload; size cap; preview saves nothing and returns the tree and warnings (no headings, long sections, duplicate headings).
- [ ] E3 Sections from headings; plain text is one section split by paragraph.
- [ ] E4 Chunks: target size, overlap, never inside code, tables or `$$`; offsets slice back to the exact text; LaTeX preserved.
- [ ] E5 An unsplittable unit over the cap fails with its reason; nothing is embedded truncated (P1.5's guard is exercised through ingest).
- [ ] E6 The document prefix is sent to the model only, and absent from stored text, `tsv` and citations.
- [ ] E7 Chunks are immutable: a new revision makes new rows, old ones stay; unchanged hashes reuse vectors with no model call (count asserted); a different model doesn't reuse.
- [ ] E8 Dimension mismatch, model failure and retry each behave as §5; a source isn't usable until `ready`.
- [ ] E9 Sources are private: another proctor gets 404; students have no route; authz matrix extended.
- [ ] E10 Against real pgvector: stored vectors round-trip; the HNSW index is used for a scoped query (`EXPLAIN`, or the reason it isn't).

**F2 Retrieval & scope**
- [ ] E11 Scope filter: a chunk out of scope can never come back, including when it's the best match.
- [ ] E12 Hybrid: a notation query (`x^T y`) finds its chunk by full text; a paraphrase finds it by vector; RRF merges them deterministically.
- [ ] E13 The query prefix is sent; a vector from a different model is never compared.
- [ ] E14 `RetrievalLog` records query, scope, chunk ids, ranks, scores, model.
- [ ] E15 Budget: chunks fit in a small and a large context window; estimate route returns count, tokens, and fit per role.

**F3 Sources UI**
- [ ] E16 Playwright: add, preview, save, watch embedding progress (announced), edit to a new revision, view with a highlighted passage.
- [ ] E17 The scope tree works by keyboard, shows the estimate and fit, and math renders with MathML.
- [ ] E18 axe clean in every state and at 320 px.

**F4 Sessions, objectives, blueprint**
- [ ] E19 Sessions are owner-scoped; a session can't use another user's source.
- [ ] E20 Objectives: heading starts, model proposal per section (mock), each citing real chunks; a citation to an unknown chunk is rejected; edit, merge, remove, add.
- [ ] E21 Role unassigned: headings only, with a notice; `embeddings` unassigned blocks authoring with a reason.
- [ ] E22 Blueprint: each test type fills SPEC's defaults; every value can change; proportional spread uses token counts, minimum one per objective.
- [ ] E23 The style line reaches the prompt, versioned.

**F5 Generation & validation** (against the mock unless stated)
- [ ] E24 Batches split by objective; streamed; calls pass the per-endpoint queue; context budget respected; only sent chunks can be cited.
- [ ] E25 A failed batch of each kind (incomplete, invalid, timeout) shows with its code and retries; salvage keeps valid items and shows `failedItems`.
- [ ] E26 Cancel stops a running generation, including queued calls.
- [ ] E27 SSE: progress events arrive; a reconnect recovers state; authz holds.
- [ ] E28 Mapper: all five types; ids 1..n; `topics_covered` from objectives; `correctAnswer` from the correct option or computed value.
- [ ] E29 L1: every SPEC rule has a passing and a failing case, including the placeholder checks and the "no placeholders" batch.
- [ ] E30 L2: exact; normalized; fuzzy above and below threshold; unknown chunk fails.
- [ ] E31 L3: each heuristic; the P6 number check allows numbers in the cited passage.
- [ ] E32 Flow A through real generation output: answer computed, options built, `QuestionEvent answer_computed`, runs linked to the draft question.
- [ ] E33 Input values come from the cited chunk first, once per test; `source` values must appear in a quote.
- [ ] E34 Disguised calculation → fail and regenerate reason; symbol-only definition passes.
- [ ] E35 A prompt-injected source whose program attempts a socket: denial, question fails, audit row, chunks flagged.
- [ ] E36 The truncation and `<think>` notes in §5 are settled, with tests.

**F6 Review & revise**
- [ ] E37 Split view: question, source passage with quote highlighted, programs and results.
- [ ] E38 Accept / edit / reject / regenerate with note / lock; each writes a `QuestionEvent`; a blocked question can't be accepted.
- [ ] E39 Filters by fail, warn, objective; badges carry text as well as color.
- [ ] E40 Inline edit re-validates; a computable edit re-runs flow B; the answer can't change without the check.
- [ ] E41 Reclassify needs a note, and is recorded.
- [ ] E42 Programs disagree: both shown, choosing one records `fix_accepted`; accept-fix applies only on confirmation.
- [ ] E43 Revise: only the named questions are sent as questions; locked ones are context and unchanged; a new numbered revision.
- [ ] E44 Question history shows the whole chain with who, what and why.
- [ ] E45 Playwright + axe through the review flow, keyboard only, at 320 px, with announcements.

**F7 Publish & provenance**
- [ ] E46 Publish makes an immutable `TestVersion` with only accepted questions; a failing or unanswered question blocks it.
- [ ] E47 The published test works in P1 practice, unchanged, through Result export.
- [ ] E48 Provenance is complete and stays readable after the session is deleted.
- [ ] E49 Source change: banner, re-validate re-runs L2; published citations still resolve to the old chunks.
- [ ] E50 `proctorReady` on the published version is right for both outcomes.

**Whole phase (F8)**
- [ ] E51 Eval `grounding-smoke` (`authoring.generate`): retrieved chunks → questions; L1–L3 pass rates, on the mock in `bun run ci`. `retrieval-mini` runs through pgvector and hybrid too.
- [ ] E52 Live, end to end on the reference setup: ingest a repo fixture source, propose objectives, generate a `chapter_quiz` of ≥ 10 questions, L1–L3 + L7, publish, take it in practice. Pass rates, seconds per question and failures recorded in the audit. **Blocked** if the box can't be reached.
- [ ] E53 SPEC §13 Q4 and Q5 are updated with what E52 measured.
- [ ] E54 Compose: the full stack passes the journey in E52 with the mock, or live if reachable.
- [ ] E55 `bun run ci` passes from a clean clone with no model server reachable; `no-literal-ui-string` and catalogs pass.
- [ ] E56 Every §5 decision that changed SPEC is logged in §15.2 and reflected in §3A, §3C, §4, §10, §12; `docs/DEVELOPMENT.md` covers ingest and authoring.

## 9. Environment prerequisites

As P2.1. Postgres with pgvector, from the local binaries or Compose. The reference Ollama endpoint for E52 only, with thinking off through `LLM_DEV_PARAMS`, as P2.1 §9. Nothing else in `bun run ci` needs a model server: extend the mock for objectives and generation.
