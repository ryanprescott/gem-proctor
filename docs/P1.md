# P1 – Practice (build spec)

> Companion to [`SPEC.md`](SPEC.md) (v0.22). This file says **what P1 builds and how it's checked**. Where the two disagree, `SPEC.md` wins. Fix the discrepancy here, or log a change in SPEC §15.
> Written for a single uninterrupted build ("zero-shot"), **one feature at a time**: each feature ends with its own audit section and its own commit before the next one starts (§10).

---

## 1. Goal

Practice mode on top of the P0 skeleton: a user takes one of their tests as often as they like, gets immediate feedback on each question, sees a graded results screen with a per-topic breakdown, retakes the questions they missed, keeps a history of attempts, and exports any attempt as a `Result` file. Grading is server-side and authoritative, with short-answer normalization and a recorded self-graded override.

Source: SPEC §14, row P1; §6 (practice mode), §7.1–7.2 (grading), §2.2 / §4 (Result).

## 3. Out of scope (do not build)

Groups, join codes, `PracticeAvailability` (students practising a proctor's test; P3, needs groups), assignments, submissions, time limits, accommodations, proctored grading, `needs_review` queue, `GradeOverride`, AI analysis (the "Analyze with AI" button is **not rendered**: no `analysis` role exists until P1.5/P3.1), the LLM layer, sources, trend charts. Tables for these are **not** created in P1. `Response` gets no `submissionId` column yet (P3 adds it).

## 4. Database (P1 tables)

From SPEC §10, plus the columns P1 needs (logged in SPEC §15.2 at the end of the phase):

```
PracticeAttempt(id, userId, testVersionId, kind: full|retake_missed, shuffleSeed, questionIds int[]?, startedAt,
                submittedAt?, durationMs?, score?, maxScore)
Response(id, attemptId, questionId int, answer jsonb?, autoResult: correct|partial|incorrect?, pointsAwarded,
         selfGraded, flagged, answeredAt?, timeSpentMs, UNIQUE(attemptId, questionId))
```

- `questionIds`: null for a `full` attempt; the subset (by question `id`) for `retake_missed`. SPEC §10 has no column for this, and deriving it from the previous attempt later would be fragile.
- **At most one in-progress attempt per user per test version:** partial unique index on `(userId, testVersionId) WHERE submittedAt IS NULL`.
- `score` is null until submit; `maxScore` is set at start (sum of `points ?? 1` over the attempt's questions). Points are fractional: store them so that they round-trip exactly to two decimals (same rounding as `toResult`).
- `answer`: a string, or a string array for `multi_choice`; null while the question has only been flagged or visited.
- `needsReview` from SPEC §10 is not a column yet: it only exists in proctored mode (§7.2), so P3 adds it.
- `Response.attemptId` is `NOT NULL` with `ON DELETE CASCADE`; P3 makes it nullable when it adds `submissionId` (with a check that exactly one is set).
- `gem_app` gets `SELECT, INSERT, UPDATE, DELETE` on both tables (grants migration, like P0).
- Practice actions are not admin actions: **no `AuditLog` rows**. The self-graded flag on the response is the record (§6 of SPEC).

## 5. Decisions made for P1

These were left open in SPEC; P1 settles them. If one doesn't hold up, change it and log it in SPEC §15.2.

| Decision | Choice | Resolves |
|---|---|---|
| Who can practise in P1 | The test's **owner** (proctor) and admins, on tests they own. Students have no practisable tests until P3 adds groups and `PracticeAvailability`; their home page says so | §5.1, §6 |
| Attempt privacy | Attempts are loaded by `(id, userId = caller)`; anyone else, **admins included**, gets 404. The admin `*` policy line doesn't reach attempts because the lookup is scoped by user. Logged as the reconciliation of §5.1 ("admins see everything") with §6 ("private to the user") | §5.1, §6 |
| Which version | "Take test" pins the test's **latest** `TestVersion`. "Retake missed" pins the version of the attempt it retakes. Archived tests can't be started (409 `test_archived`); their history stays visible | §6, §9.1 |
| In-progress attempt exists | `POST /practice/attempts` returns 409 `practice_attempt_in_progress` with `{ attemptId }`. The UI offers **Resume** or **Discard** (`DELETE`, only while in progress) | §6 |
| Locking after feedback | A question's answer is **checked** once ("Check answer"), the server grades it and returns the feedback, and the answer is then locked (409 `practice_answer_locked`). Without the lock, immediate feedback would make the score meaningless. `flagged` and `timeSpentMs` stay writable until submit | §6 |
| Feedback source | The UI shows the server's graded response. The attempt DTO still includes correct answers and explanations (§6: practice sends them), so a test may assert the client and server agree | §6, §7.1 |
| Autosave | Each check, flag toggle and question change saves (`PUT …/responses/:questionId`). An answer typed but not yet checked is kept in `sessionStorage` per attempt + question, so a refresh restores it too. Resume reopens the first unanswered question | §6 |
| Shuffle | Seed: 128 random bits, stored as hex. PRNG and Fisher–Yates in `packages/shared` (no `Math.random`). Question order and each question's option order are shuffled; `true_false` options keep `True, False` order. The server applies the shuffle in `GET /practice/attempts/:id`, so the DOM order is the display order | §6, §1.3 |
| Time per question | The client counts time while a question is displayed and the document is visible, and sends the **cumulative** `timeSpentMs`. The server keeps `max(stored, sent)`, capped at time since `startedAt`. `durationMs = submittedAt − startedAt`, computed by the server | §6 |
| Soft timer | Shows elapsed time, never ends the attempt, not announced by screen readers on every tick (`role="timer"`, polite live region off); an "Elapsed time" label is always readable | §1.3, §6 |
| `multi_choice` partial credit | `partialCredit: "all_or_nothing"` (default) or `"proportional"`: `points × max(0, (correctSelected − wrongSelected) / |correctAnswers|)`, rounded to 2 decimals. `autoResult` is `partial` when 0 < points < max | §7.1 |
| Numeric answers | Trim, NFKC, unify minus signs, strip one pair of surrounding `$`, then a plain decimal or exponent number (`-1`, `+2.5`, `1e-3`, `.5`). No thousands separators, fractions or units: anything else is incorrect, not an error | §7.1 |
| Short-answer ignore list | Per question: `ignoreWords?: string[]` (trailing words/units stripped, §7.2). No instance-wide list in v1 | §7.2 |
| Self-graded override | Only on `short_answer` responses graded incorrect, during the attempt (after the check) or on the results screen; it can be undone. Sets `selfGraded = true`, `pointsAwarded = points`; the score is recomputed. Shown as "self-graded" everywhere, and exported as `selfGraded: true` with `userIsCorrect: true` | §6, §7.2 |
| Retake missed | "Missed" = every question of the **most recent submitted** attempt of that test (either kind) that didn't get full points after self-grading, unanswered ones included. None missed → the button is disabled and the API returns 409 `practice_nothing_to_retake` | §6 |
| Unanswered at submit | Allowed after a confirmation dialog stating how many are unanswered; they score 0 and export with `userAnswer: ""`, `userIsCorrect: false` | §2.2 |
| Topic breakdown | Grouped by question `topic` in order of first appearance, each with correct / total and points; `topics_covered` is listed above it. No fuzzy matching of `topic` to `topics_covered` entries (P2's objectives will give a real mapping) | §6 |
| Cited source passage | Imported tests have none; the review shows `evidence[].quote` when present, nothing otherwise | §6 |
| Result export | `GET /practice/attempts/:id/export` → `toResult` over the attempt's questions in **original** quiz order (not shuffled), with `mode: "practice"`, `attemptId`, `startedAt`, `submittedAt`, and the stored grades (not re-graded). A retake-missed export holds only its subset, with `total_questions` recomputed. 409 `practice_attempt_not_submitted` before submit | §2.2, §4 |
| Self-grade route | `POST /practice/attempts/:id/responses/:questionId/self-grade` `{ right: boolean }` and `DELETE /practice/attempts/:id` are added to SPEC §12 | §12 |

## 6. Routes in P1

All under `/api/v1`, each with a shared Zod contract and a Casbin declaration. New object type `practice_attempt`; starting an attempt also checks `test` / `practice` on the test (owner).

```
Proctor+    POST   /practice/attempts                      { testId, kind: "full" | "retake_missed" }  (test owner, or admin)
(own only)  GET    /practice/attempts?testId=              history, newest first
            GET    /practice/attempts/:id                  attempt + shuffled questions (with answers) + responses
            PUT    /practice/attempts/:id/responses/:questionId   { answer?, check?: true, flagged?, timeSpentMs? }
            POST   /practice/attempts/:id/responses/:questionId/self-grade   { right: boolean }
            POST   /practice/attempts/:id/submit
            DELETE /practice/attempts/:id                  in progress only
            GET    /practice/attempts/:id/export           Result JSON (submitted only)
```

New error codes (each with an `errors:<code>` catalog entry): `test_archived`, `practice_attempt_in_progress`, `practice_attempt_submitted` (write after submit), `practice_attempt_not_submitted`, `practice_answer_locked`, `practice_nothing_to_retake`, `practice_question_not_in_attempt`, `practice_self_grade_not_allowed`.

Web pages: test detail gains a **Practice** section (Take test, Retake missed, Resume / Discard, history table); **attempt** page `/practice/attempts/:id`; **results** page `/practice/attempts/:id/results`. Home (proctor+) shows the five most recent attempts; home (student) says practice tests appear once a proctor shares one (P3).

## 7. Build order (one commit per feature)

Each feature is finished, tested, audited and committed before the next starts (§10). The commit message names the feature: `P1: <feature>`.

1. **F1 Grading & shuffle** (`packages/shared`): S1, S2, S3 with unit and property tests; JSON Schema export updated. Criteria B1–B9.
2. **F2 Practice data & authz** (`packages/db`, `packages/authz`, shared contracts + error codes): S4, S5, contracts for every §6 route. Criteria B10–B12.
3. **F3 Practice API** (`apps/api`): S6 with integration tests against real Postgres; authz matrix extended. Criteria B13–B22.
4. **F4 Test-taking UI** (`apps/web`): S7, with Playwright + axe. Criteria B23–B29.
5. **F5 Results, retake & history UI**: S8, S9, home page entries, with Playwright + axe. Criteria B30–B35.
6. **F6 Phase close**: the whole-phase checks B36–B38, SPEC update (§10), `docs/DEVELOPMENT.md` if anything changed.

## 8. Acceptance criteria (the audit checklist)

Each line is checked by a test, a command, or reading the code. The audit marks each **pass / fail / partial / blocked** with evidence. P0's criteria A1–A33 must keep passing; a P1 change that breaks one is a P1 failure.

**F1 Grading & shuffle**
- [ ] B1 Every question type has passing and failing `gradeResponse` tests: `single_choice`, `true_false` (exact option match), `multi_choice` (set equality, order-independent), `numeric` (tolerance 0 and > 0, boundary `|Δ| = tolerance` is correct), `short_answer` (`correctAnswer` and each `acceptedAnswers` entry).
- [ ] B2 Short-answer normalization: one test per §7.2 rule (trim/whitespace, case fold and `caseSensitive: true`, whitespace around each of `[ ] , ( ) ^ _ + - * /`, NFKC, minus signs and quotes, `ignoreWords`). `[4, 2, 3]^T` matches `[4,2,3]^T`; `2n - 1 flops` matches `2n-1` with `ignoreWords: ["flops"]`.
- [ ] B3 Numeric parsing accepts exactly the forms in §5 and treats everything else (`1,000`, `1/2`, `3 m`, empty) as incorrect without throwing.
- [ ] B4 Partial credit: `all_or_nothing` and `proportional` table tests, including more wrong than right selections (→ 0) and fractional `points`; `autoResult` is `partial` where expected.
- [ ] B5 `gradeQuestion` (P0) and `toResult` use the new grader; P0's A11 tests still pass unchanged.
- [ ] B6 `shuffleAttempt` is deterministic for a seed, a permutation (no question or option lost or duplicated), keeps `true_false` order, and differs across seeds (property test over the fixture).
- [ ] B7 With the fixture's Q7 fixed (`correctAnswer: "-1"`), `"-1"` is correct and `"1"` is incorrect: grading compares exactly and never snaps an answer to a nearby option.
- [ ] B8 `partialCredit`, `ignoreWords` and `selfGraded` are optional, base files still parse (A5 still passes), and `/schema/quiz.json` / `result.json` include them (staleness check passes).
- [ ] B9 A `Result` with `selfGraded: true` passes `Result` validation and `recomputeScore` counts its points.

**F2 Practice data & authz**
- [ ] B10 Migration creates `practice_attempt` and `response` with the §4 constraints: unique `(attemptId, questionId)`, partial unique in-progress index (inserting a second in-progress attempt for the same user and version fails), cascade delete of responses.
- [ ] B11 `gem_app` can read and write both tables; `audit_log` grants are unchanged (A21 still passes).
- [ ] B12 Every §6 route has a contract and a declaration; the startup check (A16) covers them.

**F3 Practice API**
- [ ] B13 Start: `full` pins the latest version, stores seed and `maxScore`; `retake_missed` stores exactly the missed `questionIds` of the most recent submitted attempt and pins its version; 409 codes for in progress, archived test, nothing to retake.
- [ ] B14 `GET /practice/attempts/:id` returns questions in the seeded order with shuffled options; two attempts with different seeds differ; the same attempt is stable across requests.
- [ ] B15 Saving: `check: true` grades on the server and returns outcome, points, correct answer and explanation; a second check or answer change → 409 `practice_answer_locked`; `flagged` and `timeSpentMs` update after a check; a question outside the attempt → 404/409 `practice_question_not_in_attempt`; any write after submit → 409 `practice_attempt_submitted`.
- [ ] B16 `timeSpentMs` keeps the max and is capped at time since start; `durationMs` is computed by the server at submit.
- [ ] B17 Submit stores `score` (incl. self-grades) and `submittedAt`; unanswered questions score 0.
- [ ] B18 Self-grade: allowed only on incorrect `short_answer` responses (else 409 `practice_self_grade_not_allowed`), works before and after submit, can be undone, and the stored score follows.
- [ ] B19 History lists only the caller's attempts for that test, newest first, with score, `maxScore`, duration, kind, status.
- [ ] B20 Export: the downloaded file passes `Result`, is in original quiz order, carries `mode`, `attemptId`, `startedAt`, `submittedAt`, `selfGraded`; it re-imports as a quiz through `POST /imports/preview` with no errors; a retake-missed export has only its subset. 409 before submit.
- [ ] B21 Authz matrix (A17 extended): anonymous, student, proctor owner, proctor non-owner, admin × every §6 route. Students get 403 on start; a non-owner proctor can't start on someone else's test; **another user's attempt id is 404 for everyone, admins included**.
- [ ] B22 Discard deletes an in-progress attempt and its responses, and refuses a submitted one.

**F4 Test-taking UI**
- [ ] B23 Starting an attempt from the test detail page shows question 1 of N in the seeded order; options are a real radio group (`single_choice`, `true_false`) or checkbox group (`multi_choice`), text field for `short_answer` / `numeric`.
- [ ] B24 Checking an answer shows correct/incorrect (text and icon, not color alone), the correct answer and the explanation, and announces the outcome through the live region (A32 pattern).
- [ ] B25 Flag for review is a toggle button (`aria-pressed`); the question navigator shows answered / flagged / current state in text, is keyboard-operable, and announces the position.
- [ ] B26 Soft timer shows elapsed time with `Intl` formatting and never ends the attempt; `timeSpentMs` reaches the server.
- [ ] B27 Reload mid-attempt resumes the same attempt: checked answers, flags and an unchecked typed answer are restored.
- [ ] B28 Submit with unanswered questions asks for confirmation (accessible dialog, focus managed) and then shows the results page.
- [ ] B29 axe reports zero violations on the attempt page in each state (unanswered, after correct and incorrect feedback, flagged, submit dialog open), and at 320 px width.

**F5 Results, retake & history UI**
- [ ] B30 Results show score, percentage (`Intl`), time taken, and each question with your answer, the correct answer, explanation, evidence quote if present, and points.
- [ ] B31 The per-topic breakdown matches the stored grades (test with a fixture of known answers).
- [ ] B32 "I was right" on an incorrect short answer updates the score on screen and in history, shows "self-graded", announces the change, and can be undone.
- [ ] B33 Retake missed starts an attempt with exactly the missed questions; it's disabled when nothing was missed. Retake starts a full attempt.
- [ ] B34 Export downloads a Result file whose contents match the screen.
- [ ] B35 History on the test detail page lists attempts with score, date and duration (`Intl`), links to results, and Resume / Discard for an in-progress one; axe zero violations on test detail (with history) and results pages.

**Whole phase (F6)**
- [ ] B36 Keyboard-only Playwright test: sign in → test detail → Take test → answer and check every question (one short answer wrong) → flag one → submit → "I was right" → Retake missed → finish → export.
- [ ] B37 `no-literal-ui-string` passes with an empty or justified suppression baseline; the catalog check covers every new key and error code; `bun run ci` passes from a clean clone.
- [ ] B38 Every §5 decision that changed SPEC behaviour or added a field, column or route is logged in SPEC §15.2 and reflected in the spec text (§4, §6, §10, §12).

## 10. Build and audit procedure (per feature)

For each feature F1–F5, in order:

1. Build it, with its tests. Keep `SPEC.md` in mind: a decision in §5 that turns out wrong is changed here and noted for the SPEC log.
2. Run `bun run ci`. It must pass in full (P0 criteria included); fix anything it reports before going on.
3. Audit the feature's criteria from §8 and **append** a section `## F<n> <name>` to `docs/P1-audit.md`: a table with pass / fail / partial / blocked and evidence (test name, command output, or file:line) per criterion, the `bun run ci` summary, and any deviations from SPEC or this file. A `fail` is fixed before the commit; a `blocked` says what unblocks it.
4. Commit on `main` with only that feature's changes plus its audit section: `P1: <feature>` (e.g. `P1: grading and shuffle`), a body listing what was built, and the attribution line. Don't start the next feature with failing checks or uncommitted work.
5. If a later feature has to change an earlier one, that change goes in the later feature's commit, and the earlier audit row is updated in the same commit with a note.

Then **F6**: check B36–B38, re-run every earlier criterion that the later features touched, write the summary table at the top of `docs/P1-audit.md` (counts per result, blocked list, deviations), update SPEC (bump to v0.23, add the "Last updated" entry, fix the header's stale "Draft v0.17" label, log §5 decisions in §15.2, update §4, §6, §10, §12), and commit `P1: phase audit; spec v0.23`.
