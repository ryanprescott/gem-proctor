**Deviations and notes.**
- As in P1's F2, the LLM routes are registered with a placeholder handler (503 `service_unavailable`) so the startup checks and the matrix cover them from F1; F3 replaces it.
- `LlmCallLog.promptFile` is an extra column: the template file used, for C29's "the variant file is recorded". `LlmCallLog.outcome` is `ok | salvaged | failed`, so stats can compute the salvage rate.
- `LlmEvalRun` has a partial unique index on `role` while `queued` or `running`, so `llm_eval_running` holds under concurrent requests.
- `Endpoint.createdBy`, `RoleAssignment.updatedBy` and `LlmEvalRun.startedBy` are nullable: the dev seed and the CLI have no actor.
- `PUT /admin/settings` takes `localEndpointsOnly` as optional; a setting left out keeps its value (the settings form sends only `selfRegistration`).
- `ENDPOINT_SECRET_KEY` must now be exactly 32 bytes (it was "at least 32"): AES-256 takes exactly that.
- `apps/web/e2e/practice.e2e.ts` and `practice-keyboard.e2e.ts`: found failing at the start of P1.5 (a race, not a product bug). `getByText("Correct", { exact: true })` also matches the live region once it has announced, so the strict locator failed on a slower run. They now look for the `<strong>` label, and the live region is still checked by the `liveRegionText` line after each.
- `apps/web/src/routes/Attempt.tsx`: B36 also failed now and then, and that one was a real keyboard bug: `AnswerInput` wasn't keyed by question, so when two radio questions came next to each other in the seeded order the group's roving tab stop stayed on an option of the previous question and Tab skipped the new radios. Keyed by question id; Playwright passed three times in a row, then in the full run above.
