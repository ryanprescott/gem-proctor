**Deviations and notes.**
- As in P1's F2, the LLM routes are registered with a placeholder handler (503 `service_unavailable`) so the startup checks and the matrix cover them from F1; F3 replaces it.
- `LlmCallLog.promptFile` is an extra column: the template file used, for C29's "the variant file is recorded". `LlmCallLog.outcome` is `ok | salvaged | failed`, so stats can compute the salvage rate.
- `LlmEvalRun` has a partial unique index on `role` while `queued` or `running`, so `llm_eval_running` holds under concurrent requests.
- `Endpoint.createdBy`, `RoleAssignment.updatedBy` and `LlmEvalRun.startedBy` are nullable: the dev seed and the CLI have no actor.
- `PUT /admin/settings` takes `localEndpointsOnly` as optional; a setting left out keeps its value (the settings form sends only `selfRegistration`).
- `ENDPOINT_SECRET_KEY` must now be exactly 32 bytes (it was "at least 32"): AES-256 takes exactly that.
- `apps/web/e2e/practice.e2e.ts` and `practice-keyboard.e2e.ts`: found failing at the start of P1.5 (a race, not a product bug). `getByText("Correct", { exact: true })` also matches the live region once it has announced, so the strict locator failed on a slower run. They now look for the `<strong>` label, and the live region is still checked by the `liveRegionText` line after each.
- `apps/web/src/routes/Attempt.tsx`: B36 also failed now and then, and that one was a real keyboard bug: `AnswerInput` wasn't keyed by question, so when two radio questions came next to each other in the seeded order the group's roving tab stop stayed on an option of the previous question and Tab skipped the new radios. Keyed by question id; Playwright passed three times in a row, then in the full run above.

**Deviations and notes.**
- `generateText` / `streamText` with a small custom `Output` instead of the SDK's `generateObject` / `streamObject`: those validate and throw on their own, and the repair loop needs the raw text. The JSON Schema still goes through the SDK's `responseFormat`, so §15.1's contingency isn't triggered.
- `params` go through a `fetch` wrapper in the adapters, not `providerOptions`: the same code path for both providers, and the values reach the body unchanged (the SDK warns about and drops `top_k` on `openai-compatible` otherwise).
- `strict: false` in `response_format`: local servers ignore it and constrain decoding either way, and OpenAI-style clouds refuse optional fields under `strict: true`.
- A repair is self-contained: `output-repair-v1` as the system message, the issues, invalid output and schema as the user message. The original prompt isn't re-sent, so a repair stays within the context budget. Each attempt goes through the queue separately; `queuedMs` and `latencyMs` are summed.
- A call on an unassigned role isn't logged: `LlmCallLog.endpointId` is required and there's no endpoint. A call aborted by its caller rethrows the signal's reason (not an `LlmError`: it isn't a model failure) and logs `errorCode: aborted`.
- `embed`'s `tokens[]` is exact for a text sent alone, otherwise its share (by characters) of its batch's `prompt_tokens`. As §5 decides, batching relies on the chars ÷ 3 estimate: a text below half of `maxInputTokens` by estimate but with far fewer characters per token than 3 (e.g. CJK) is batched, where a truncation wouldn't show in the count. The chunker (P2) should stay well under the cap, as SPEC §3C.2 says.
- Salvage returns the object with only the valid items; a rule on the array itself (e.g. `.length(4)`) doesn't apply to a partial batch, but an invalid field outside the array is still `llm_output_invalid`.
- Prompt-file versions come from `ACTIVE_PROMPTS` in `src/prompts.ts`; only `output-repair` is listed until F4.
