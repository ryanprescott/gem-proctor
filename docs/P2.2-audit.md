# P2.2 audit

Audit of P2.2.md §8, feature by feature, each section written when its feature was finished (P2.2.md §10). Each criterion is **pass**, **fail**, **partial**, **blocked** or **dropped**, with evidence.

**Environment.** WSL2 with Docker and Compose, default runtime runc. Postgres 17 + pgvector 0.8 and Python 3.12 from the local binaries. The vision model, Surya 2.5, runs as a model in the Ollama box's Ollama (RTX 3060, 12 GB), reached over Tailscale; Marker 2.1.0 runs here, in the converter container.

**Deviations and notes.**
- **The request is the raw PDF as the body, with the options in a header** (`x-gem-options`), not multipart: a multipart parser is not in the standard library, and the service stays standard-library only so its tests run anywhere.
- **The service is not FastAPI**, for the same reason; `http.server` with threads is enough for one conversion at a time.
- **Pages are rendered and converted in batches of ten**, so a long document holds a few pages of images at once, not all of them.
- **Marker's `--force_ocr` produced an empty file with exit code 0** in the spike; the worker turns any empty result into `empty`, whichever flag caused it.
- **The weights are baked into the image** (a layout model from Hugging Face, an OCR-error detector from Datalab's storage), after the first build found the second was fetched on first use, which an offline, read-only image can't do. Surya writes its lock and log files under `~/.cache`, so `HOME` is a tmpfs.
- **The development shim** in front of Ollama (Surya wants `/health` and a model id without `:latest`) lives in the service until F2's proxy replaces it.
- **The scoring** is in `packages/convert`, tested against the fixtures' own Markdown (which must score 54 of 54): its first version replaced `\cdot` before `\cdots`, which the test caught.
- **Not in `bun run ci`:** `convert:check`, `live:convert` and the image build: the image is 3.3 GB and the checks need Docker and the box. Run them after changing the image, the Compose service or the engine.

**Deviations and notes.**
- **The proxy isn't a contract route.** It has no session, only the shared secret, and sits under `/internal/vlm/v1`; it is declared public to the permission check and refuses without the secret. The converter must be pointed at it (`SURYA_INFERENCE_URL`) with the secret as its key. That wiring, in Compose, replaces the development shim and is done with the F4 live run.
- **A page read is not streamed**: the proxy forces `stream: false`.
- **Idle detection is in-process plus the database**: generation and L7 handlers are counted in this process, and queued or running batches are looked up, so a batch that is queued but not started also holds a conversion back. A draft's L7 job that is queued but not running does not.
- **A deleted file stays in the table** (soft delete) because revisions point at it.

## F3 Web

Built: on the add-source page, a "Or read a PDF" group (`SourcePdf.tsx`): an optional page range checked as it is typed, a PDF chooser, the upload (raw body, `api.upload`), progress over the file's event stream announced once per change, a failure in words with a retry, and, when it is done, the Markdown put in the text box for editing with the converter's warnings and a rendering of the text and equations (KaTeX, with MathML). Equations the browser can't read are found with `findUnparsedMath` and listed as written. Saving sends `fileId`; the source page links the original PDF for each revision made from one. `bun run e2e` starts the mock converter (`MockConvertServer`, now with named documents) and gives the API its address; the PDF tests skip against a stack started elsewhere. Tests: `apps/web/e2e/pdf.e2e.ts` (4), `apps/web/test/math.test.ts` (4).
