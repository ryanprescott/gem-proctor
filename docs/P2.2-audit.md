**Deviations and notes.**
- **The request is the raw PDF as the body, with the options in a header** (`x-gem-options`), not multipart: a multipart parser is not in the standard library, and the service stays standard-library only so its tests run anywhere.
- **The service is not FastAPI**, for the same reason; `http.server` with threads is enough for one conversion at a time.
- **Pages are rendered and converted in batches of ten**, so a long document holds a few pages of images at once, not all of them.
- **Marker's `--force_ocr` produced an empty file with exit code 0** in the spike; the worker turns any empty result into `empty`, whichever flag caused it.
- **The weights are baked into the image** (a layout model from Hugging Face, an OCR-error detector from Datalab's storage), after the first build found the second was fetched on first use, which an offline, read-only image can't do. Surya writes its lock and log files under `~/.cache`, so `HOME` is a tmpfs.
- **The development shim** in front of Ollama (Surya wants `/health` and a model id without `:latest`) lives in the service until F2's proxy replaces it.
- **The scoring** is in `packages/convert`, tested against the fixtures' own Markdown (which must score 54 of 54): its first version replaced `\cdot` before `\cdots`, which the test caught.
- **Not in `bun run ci`:** `convert:check`, `live:convert` and the image build: the image is 3.3 GB and the checks need Docker and the box. Run them after changing the image, the Compose service or the engine.

**Deviations and notes.**
- **The proxy isn't a contract route.** It has no session, only the shared secret, and sits under `/internal/vlm/v1`; it is declared public to the permission check and refuses without the secret. The converter must be pointed at it (`SURYA_INFERENCE_URL`) with the secret as its key. That wiring, in Compose, replaces the development shim and is done with the F4 live run.
- **A page read is not streamed**: the proxy forces `stream: false`.
- **Idle detection is in-process plus the database**: generation and L7 handlers are counted in this process, and queued or running batches are looked up, so a batch that is queued but not started also holds a conversion back. A draft's L7 job that is queued but not running does not.
- **A deleted file stays in the table** (soft delete) because revisions point at it.

**What F4 found, and what changed.**
- **The proxy couldn't have worked with Surya.** Surya, given `…/internal/vlm/v1`, checks health one level up, at `…/internal/vlm/health`, and sends no key on its health and model checks; F2's proxy answered `…/v1/health` and wanted the secret on both. Now health is at Surya's path and both checks are open (they say "ok" and a fixed model id); a page read still needs the secret. F2's tests called the proxy directly, not through Surya; they now use Surya's paths and keys.
- **Surya's llama.cpp client always sends the key `EMPTY`.** The converter uses its vLLM client (`SURYA_INFERENCE_BACKEND=vllm`), which sends `VLLM_API_KEY`; with the URL given, no server is started. Compared before choosing: `convert-smoke` scored the same with the llama.cpp client through the shim, the vLLM client through the shim, and the vLLM client through the proxy.
- **The secret is in the converter's environment,** not a Compose secret: Compose refuses an environment-sourced secret in a read-only container, and a file would be as readable to a compromised converter. `check-convert.ts` allows that one name and still fails any other secret-like one.
- **Marker drops a page's first line as a page header.** On the re-typeset fixtures that was the end of a sentence across the page break ("…of columns of $A$ equals the number of rows of $B$.", 52 of 54 formulas), and on every run since the spike the document's title. Shown in Marker's own output, before our clean-up. `keep_pageheader_in_output` brought back both: 54 of 54 and 5 of 5 headings; `text` went from 32 to 39. Our clean-up already drops a short line that repeats on three or more pages, so a book's real running headers still go. Footers stay dropped (page numbers).
- **Marker repeats a paragraph** ("Norms and distance", with small differences in the second copy): 63 formulas in the output for 54 expected, on every layout, the old fixtures included. Not removed: deduplicating near-copies risks deleting real repetition. The creator sees it in the preview.
- **The API image didn't build:** `packages/convert` wasn't copied into its install stage, so `bun install --frozen-lockfile` failed (F2 added the workspace). `check-compose` runs only in GitHub CI, which this branch hasn't been through.
- **The dev seed made an embeddings assignment the API refuses:** `maxOutputTokens` from the chat model's 32k context (8192) against the embedding model's 4096. It wrote to the database past the validation, so it never showed. It now takes a share of its own window, and a test checks every seeded assignment against the API's schema.
- **The e2e suite hit the login limit** (20 a minute) on this faster machine: 2 specs failed with 429 and 5 didn't run. The e2e API now gets `AUTH_RATE_LIMIT_MAX=1000`, as the API tests do; the limit itself is tested in `auth.test.ts`.

- Not measured: a long real document (a textbook chapter with tables), and the vision model's VRAM from the box itself (`nvidia-smi`); Ollama reports 1.36 GiB.
- The live stack ran under runc (no gVisor here, and none needed for the converter's checks).
