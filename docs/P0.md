# P0 – Foundations (build spec)

> Companion to [`SPEC.md`](SPEC.md) (v0.15). This file says **what P0 builds and how it's checked**. Where the two disagree, `SPEC.md` wins. Fix the discrepancy here, or log a change in SPEC §15.
> Written for a single uninterrupted build ("zero-shot"), followed by an audit against §8 below.

---

## 1. Goal

A running, tested skeleton of the whole stack, with the cross-cutting rules (audit, accessibility, i18n, authz) enforced from the first commit. Its one user-visible feature is **importing a quiz JSON, previewing and fixing it, saving it, and exporting it again**. Every later phase builds features on this skeleton without reworking it.

Source: SPEC §14, row P0.

## 3. Out of scope (do not build)

Practice attempts, grading, LLM layer, sources/knowledge base/embeddings, authoring, L1–L7, groups, assignments, proctoring, AI analysis, endpoint secrets / encryption key, Caddy, backups. Tables for these are **not** created in P0. The verify worker has no math code yet.

## 4. Database (P0 tables)

From SPEC §10, exactly these: `User` (+ `disabledAt?`, `failedLoginCount`, `lockedUntil?`), `UserSession`, `casbin_rule`, `InstanceSettings`, `Test`, `TestVersion` (`provenance` stays null for imports), `TestImportRecord`, `AuditLog`.

- **Two DB roles.** `gem_owner` owns the schema and runs migrations. `gem_app` is used by the running API and has `SELECT, INSERT, UPDATE, DELETE` on everything **except** `audit_log`, where it has `SELECT, INSERT` only. Grants live in a migration. Compose creates both roles via an init script.
- Table names are snake_case in Postgres (`audit_log`, `test_version`); TypeScript names follow SPEC §10.
- Ids: UUID v7, generated in the app.

## 6. Routes in P0

All under `/api/v1`, every one with a shared Zod contract and a Casbin declaration (or explicit `public: true`).

```
Public      GET /health   POST /auth/register   POST /auth/login   GET /schema/quiz.json   GET /schema/result.json
Any user    POST /auth/logout   GET /auth/me
Proctor+    POST /imports/preview   POST /imports
            GET /tests   GET /tests/:id   PATCH /tests/:id (title, description, tags, archive)
            GET /tests/:id/versions   GET /tests/:id/export   (owner, or admin)
Admin       GET /admin/users   PUT /admin/users/:id/roles   POST /admin/users/:id/reset-password   POST /admin/users/:id/disable
            GET /admin/settings   PUT /admin/settings
            GET /admin/audit-log   GET /admin/audit-log.csv
```

Web pages: sign in, register, home (role-aware), import (upload/paste → report → edit → save), tests list, test detail, admin users, admin settings, admin audit log, 404.

## 7. Build order

1. Scaffold workspaces, Biome, TypeScript strict, `bun test`, CI skeleton.
2. **Test run: GritQL on `.tsx`** (SPEC §11.6 test run steps 1–3). Record the result in `docs/P0-test-runs.md`. If it fails, switch per the contingency procedure *before* writing any UI.
3. **Test run: Fastify on Bun** with `@fastify/cookie`, `@fastify/rate-limit`, `@fastify/multipart`, `@fastify/swagger`, `@fastify/static`, `fastify-type-provider-zod`. Record the result. Fall back to Node 22 per §15.1 if needed.
4. `packages/shared`: schemas, error codes, `normalizeQuiz`, `toResult`, JSON Schema export, with tests.
5. `packages/db` + Compose Postgres + migrations + roles.
6. `packages/authz` + auth + bootstrap + audit.
7. Import, tests, export, admin routes.
8. Web app: shell, i18n, pages, Playwright + axe.
9. `apps/verify` skeleton + full Compose stack.

## 8. Acceptance criteria (the audit checklist)

Each line is checked by a test, a command, or reading the code. The audit marks each **pass / fail / partial** with evidence.

**Repo & tooling**
- [ ] A1 `bun install && bun run ci` passes from a clean clone. `ci` runs: biome check, rule build staleness, lint-rule snapshot, suppression baseline, catalog check, typecheck, `bun test`, ruff, Playwright + axe (against Compose).
- [ ] A2 `docker compose up` brings up postgres, api, web, verify; `GET /api/v1/health` reports db, queue and verify all ok.
- [ ] A3 TypeScript `strict` everywhere; no `any` in `packages/shared` public types.
- [ ] A4 `docs/P0-test-runs.md` records both test runs (versions, result, evidence). SPEC §11.6 "Active implementation" and §15.2 are updated if a contingency was taken.

**Schemas & normalizer**
- [ ] A5 The fixture `tests/engr108_chapter1_new_20q_quiz.json` parses as `BaseQuiz` unchanged, and fails `Quiz` validation with **exactly one** error: Q7's `correctAnswer` not in `options`.
- [ ] A6 Every cross-field check in SPEC §4 has a passing and a failing unit test.
- [ ] A7 Every row of the SPEC §3D.2 table has a unit test; each records a fix entry. Explicit test: `"1"` is **not** snapped to `"-1"`.
- [ ] A8 `normalizeQuiz` never changes question text, never invents options or answers (property test over the fixture: question texts unchanged).
- [ ] A9 Round trip: import fixture with Q7 fixed → export → byte-for-byte equal to a re-import's export; exported base fields keep their exact names.
- [ ] A10 `/schema/quiz.json` validates the fixture (with Q7 fixed) using an independent JSON Schema validator in a test.
- [ ] A11 `toResult` produces a valid `Result`, recomputes `score`/`percentage`, and the result re-imports as a quiz.

**Auth & authz**
- [ ] A12 Passwords stored as bcrypt cost ≥ 12; inputs > 72 bytes rejected with an error code.
- [ ] A13 Session cookie is httpOnly, SameSite=Lax, Secure (Secure may be off only when `NODE_ENV=development`).
- [ ] A14 Logout and role change invalidate the cached session/decision within the same request.
- [ ] A15 Lockout after 10 failures; rate limit on login/register returns 429 with an error code.
- [ ] A16 Starting the API with a route that lacks a permission declaration fails at startup (tested).
- [ ] A17 Authz matrix test: student, proctor (owner / non-owner), admin × every P0 route → expected allow/deny. Students get 403 on all import/test routes.
- [ ] A18 Bootstrap: env admin is created once; without env, the first registration becomes admin and the second becomes student.
- [ ] A19 Self-registration off → `POST /auth/register` returns 403 with an error code.

**Audit**
- [ ] A20 Each admin action (role grant/revoke, password reset, disable, settings change, user creation via bootstrap) writes one `AuditLog` row with actor, action, target, before/after, IP, user agent. Password values never appear.
- [ ] A21 As `gem_app`, `UPDATE audit_log` and `DELETE FROM audit_log` fail with permission denied (integration test).
- [ ] A22 Audit log filter (actor, action, date range) and CSV export work; CSV is RFC 4180.

**Import UI**
- [ ] A23 Uploading the fixture shows the report with the Q7 error and blocks saving; fixing Q7 in the editor and re-running preview allows saving.
- [ ] A24 Pasting model-style text (prose + fenced JSON + trailing commas + letter answers) previews successfully and lists every applied fix.
- [ ] A25 Saved import creates `Test` + `TestVersion` + `TestImportRecord` with the raw text and report.
- [ ] A26 Test detail renders LaTeX via KaTeX with MathML present in the DOM.

**i18n**
- [ ] A27 No hard-coded UI strings: `no-literal-ui-string` passes with an empty or justified suppression baseline.
- [ ] A28 Every API error is `{ code, params }` from the shared enum; catalog check confirms each code has an `errors:<code>` entry.
- [ ] A29 Dates and percentages in the UI go through `Intl`.

**Accessibility**
- [ ] A30 axe-core reports zero violations on every page in §6 (signed out, student, proctor, admin as applicable).
- [ ] A31 Keyboard-only Playwright test completes: sign in → import fixture → fix Q7 → save → export.
- [ ] A32 Async results (preview finished, saved, errors) are announced through the live region.

**Verify skeleton**
- [ ] A33 `verify` container: `network_mode: none` (no interface besides loopback), read-only root FS, no env vars or secrets, `cap_drop: ALL` + `SETUID`/`SETGID`, `no-new-privileges`, pids/CPU/memory limits; the health request over the Unix socket returns pinned sympy/numpy versions.

## 9. Environment prerequisites

Bun installed; Docker reachable from WSL (Docker Desktop WSL integration). Until Docker works, A2, A21, A30–A31 and the Compose half of A1 can't be checked. The audit records them as **blocked**, not pass.

## 10. Audit procedure

After the build: go through §8 line by line, write `docs/P0-audit.md` with pass / fail / partial / blocked and evidence (test name, command output, or file:line) per criterion, list any deviations from SPEC, and fix or log them (SPEC §15.2) before P1 starts.
